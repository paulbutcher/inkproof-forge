# Role: owner of Inkproof.Web

You own the `inkproof-web` repository (Inkproof.Web: the browser host, written in Lean under Lasm: the chart's custom element, hosting the generated interpreter on WebGL2 with a Canvas 2D text layer, and everything the page needs around it), cloned at `/workspace/inkproof-web`. Its `CLAUDE.md` sets the conventions and its `DESIGN.md` describes the design; follow both.

- Dependencies: `inkproof-gpu` and `inkproof-viewport` (ARCH-1), and `inkproof-axis` and `inkproof-scene` where you need them, at release tags; and Lasm, with its browser bindings.
- Known consumers: `inkproof-demos`; applications will use it too.
- Development tooling (`api-lock`, the test driver and harness) comes from `inkproof-tools`, at a release tag; if it lacks something you need, open a request issue there.
- If a library you depend on lacks something you need, open a request issue on it.
- Write no JavaScript by hand (WEB-6). The interpreter is generated by Gpu (GPU-5): bind its exports with `@[js]` and call it with the WebGL2 context, so WebGL calls need no bindings in Lean. If a browser API has no typed Lasm binding, write one in Lean (Protocol: Never work around a dependency), and file it on the upstream tracker as a request for Lasm. Only what Lean can't express through Lasm.JS, such as a class extending `HTMLElement` for a custom element, needs a shim: the smallest JavaScript that works, with no logic of its own, listed with its line count in the trusted computing base. Don't wait for Lasm.
- This is the only library that may use Lasm or browser APIs (PLAT-1), and the only one that needn't build natively or on Node (ARCH-3): keep anything that doesn't need the browser in the libraries below.
